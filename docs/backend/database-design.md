# Структура баз данных

Схемы: [серверная](diagrams/server.png) и [локальная](diagrams/local.png).

## Назначение таблиц

### `User`

Профиль пользователя и его роль. Через `user_id` пользователь владеет своими курсами и историей приёмов. `encrypted_dek` хранит пользовательский ключ только в зашифрованном виде.

### `AuthCode`

Одноразовые коды входа. В базе хранится хеш кода, время использования и срок действия. Таблица есть только на сервере.

### `Medication`

Общий справочник препаратов: название, международное название, производитель, категория, форма, концентрация и ссылка на инструкцию. Одна запись может использоваться разными пользователями.

### `Course`

Курс конкретного пользователя. Даты и состояние нужны серверу для календаря, а выбранное лекарство или собственное название и заметки находятся внутри `encrypted_data`. Связь со справочником открытым `medication_id` не хранится, иначе администратор базы увидит, какое лекарство принимает пользователь.

### `Schedule`

Текущий план курса. Одна запись содержит открытые время суток и дни недели, а доза находится внутри `encrypted_data`. Несколько времён или разные дозы оформляются отдельными записями.

Курс без записей `Schedule` означает приём по необходимости.

### `Intake`

Исторический факт приёма. Он хранит владельца, фактический момент `taken_at` и зашифрованный снимок названия и дозы в `encrypted_data`.

- `user_id` обязателен;
- `course_id` может быть `null` у отдельной записи без курса;
- `schedule_id` может быть `null` у приёма вне расписания или после удаления расписания;
- заполненный `schedule_id` допускается только вместе с `course_id`.

Для отдельного приёма курс автоматически не создаётся.

## Зачем данные повторяются в `Intake`

Зашифрованная доза в `Schedule` — текущая назначенная доза. Зашифрованные данные в `Intake` — реально принятая доза и название на момент приёма.

Эти снимки нужны, чтобы изменение расписания, курса или справочника не переписало архив. Например, приём, сохранённый как `10 мг`, останется таким после изменения текущего расписания на `15 мг`.

## Удаление связей

Предпочтительна деактивация препаратов и курсов. При физическом удалении:

- расписания курса удаляются;
- `schedule_id` и при необходимости `course_id` в истории становятся `null`;
- сами `Intake` сохраняются и остаются связаны с владельцем через `user_id`.
