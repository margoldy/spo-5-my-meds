# Шифрование медицинских данных

## Схема

В браузере создаётся случайный 256-битный ключ медицинских данных. Им через `AES-256-GCM` шифруются названия лекарств пользователя, заметки и дозировки.

Пользователь задаёт отдельный пароль шифрования. `Argon2id` вместе со случайной солью получает из него ключ, которым через `AES-256-GCM` защищается ключ медицинских данных. Сервер получает только его зашифрованную версию.

Пароль не отправляется на сервер и не шифрует каждую запись напрямую. Поэтому при смене пароля заново защищается только ключ медицинских данных, а не вся история.

## Открытие данных

При вводе пароля браузер получает с сервера зашифрованный ключ и пытается открыть его. `AES-GCM` одновременно проверяет целостность результата: при неправильном пароле проверка не проходит и расшифрование завершается ошибкой.

После успешного открытия неэкспортируемый `CryptoKey` сохраняется в `IndexedDB` текущего браузера. Кнопка «Забыть устройство» удаляет эту локальную копию. На другом устройстве пароль потребуется снова.

Если пароль утрачен и открытой локальной копии ключа не осталось, сервер не может восстановить медицинские данные.

## Что хранит backend

- `User.encrypted_dek` — параметры `Argon2id`, соль, IV и зашифрованный ключ медицинских данных;
- `Course.encrypted_data` — название лекарства, ссылка на запись справочника внутри зашифрованного объекта и заметки;
- `Schedule.encrypted_data` — доза и единица измерения;
- `Intake.encrypted_data` — снимок названия и фактической дозы приёма.

Идентификаторы, связи, даты курса, дни и время расписания, время фактического приёма и состояние курса остаются открытыми. Они нужны backend для проверки владельца, выборок и построения календаря.

Зашифрованные объекты содержат версию формата, алгоритм, случайный IV и результат `AES-GCM`. Backend хранит эти строки как непрозрачные данные и не разбирает их содержимое.
