# Структура баз данных

Схемы: [серверная](../server/docs/server_bd.drawio.png) и [локальная](../server/docs/local_bd.drawio.png).

## Назначение таблиц

### `User`

Профиль пользователя и его роль. Через `user_id` пользователь владеет своими курсами и историей приёмов.

### `AuthCode`

Одноразовые коды входа. В базе хранится хеш кода, время использования и срок действия. Таблица есть только на сервере.

### `Medication`

Общий справочник препаратов: название, международное название, производитель, категория, форма, концентрация и ссылка на инструкцию. Одна запись может использоваться разными пользователями.

### `Course`

Курс конкретного пользователя: выбранное или собственное лекарство, период, состояние и заметки. Курс отделён от справочника, потому что разные пользователи принимают один препарат по-разному.

Название задаётся одним способом: через `medication_id` либо через `custom_name`.

### `Schedule`

Текущий план курса. Одна запись содержит время суток `scheduled_at`, дозу и дни недели. Несколько времён или разные дозы оформляются отдельными записями.

Курс без записей `Schedule` означает приём по необходимости.

### `Intake`

Исторический факт приёма. Он хранит владельца, фактический момент `taken_at`, фактическую дозу и снимок названия лекарства.

- `user_id` обязателен;
- `course_id` может быть `null` у отдельной записи без курса;
- `schedule_id` может быть `null` у приёма вне расписания или после удаления расписания;
- заполненный `schedule_id` допускается только вместе с `course_id`.

Для отдельного приёма сохраняется только `medication_name`, без `medication_id`, и курс автоматически не создаётся.

## Зачем данные повторяются в `Intake`

Доза в `Schedule` — текущая назначенная доза. Доза в `Intake` — реально принятая. Название в `Intake` — название на момент приёма.

Эти снимки нужны, чтобы изменение расписания, курса или справочника не переписало архив. Например, приём, сохранённый как `10 мг`, останется таким после изменения текущего расписания на `15 мг`.

## Удаление связей

Предпочтительна деактивация препаратов и курсов. При физическом удалении:

- расписания курса удаляются;
- `schedule_id` и при необходимости `course_id` в истории становятся `null`;
- сами `Intake` сохраняются и остаются связаны с владельцем через `user_id`.

## Серверная и локальная базы

Медицинские сущности в обеих схемах одинаковы, чтобы упростить синхронизацию и работу без сети.


## Соответствие моделям

Модели используют `Schedule.scheduled_at` типа `TIME`, `Intake.dose_amount` типа `NUMERIC(10, 2)` и nullable-ссылки `Intake.course_id` и `Intake.schedule_id`.

Изменения моделей Python не обновляют существующую PostgreSQL-базу автоматически. Для уже созданной базы потребуется миграция с добавлением новых полей, заполнением старых записей и только затем установкой ограничений `NOT NULL`.
