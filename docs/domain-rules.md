# Правила предметной области

Здесь описано поведение приложения. Устройство таблиц объясняется в [«Структуре баз данных»](database-design.md), защита медицинских данных — в [«Шифровании»](encryption.md), запросы — в [API](../server/docs/api.md).

## Курсы и расписание

- Курс принадлежит одному пользователю и содержит либо `medication_id` из справочника, либо введённое пользователем `custom_name`.
- `start_date` обязателен; `end_date` может отсутствовать и не может быть раньше даты начала.
- Курс без расписаний принимается по необходимости. Отдельное поле режима не требуется.
- Одна запись `Schedule` задаёт одно время, одну дозу и непустой набор дней недели от `1` (понедельник) до `7` (воскресенье).
- Для разных времён или доз создаются отдельные записи расписания.
- Завершённый курс остаётся в истории, но не создаёт будущие карточки и напоминания.

## Запись приёма

Каждый `Intake` принадлежит пользователю и хранит фактические время, дозу, единицу измерения и название лекарства.

Плановый приём:

- связан с курсом и расписанием;
- получает начальную дозу из расписания;
- позволяет исправить фактическую дозу перед сохранением.

Приём вне расписания:

- может быть связан с существующим курсом, тогда `schedule_id = null`;
- может быть отдельной записью без курса, тогда `course_id = null` и `schedule_id = null`;
- всегда требует фактическую дозу и единицу измерения.

Для записи без курса пользователь выбирает препарат из справочника или вводит название. В историю записывается только текст `medication_name`: `medication_id` не сохраняется, новый курс автоматически не создаётся.

## История и удаление

История читает название и дозу из самого `Intake`. Поэтому изменение курса, справочника или расписания не изменяет прошлые приёмы.

- Препарат обычно скрывается через `is_active = false`.
- Курс завершается через `is_active = false` или `end_date`.
- При удалении расписания его ссылка в истории становится `null`.
- При физическом удалении курса `course_id` в его приёмах становится `null`, но сами приёмы сохраняются благодаря `user_id` и снимкам данных.
- Владелец может удалить ошибочную запись `Intake`.

## Время

- API передаёт фактический момент приёма со смещением часового пояса, например `2026-09-18T09:07:00+03:00`.
- PostgreSQL хранит его как `TIMESTAMP WITH TIME ZONE`.
- Календарный день определяется в часовом поясе пользователя.
- Время в `Schedule` — время суток, а `taken_at` в `Intake` — фактический момент.

## Доступ

- Гость просматривает активные препараты справочника.
- Пользователь управляет только собственными курсами, расписаниями и приёмами.
- Администратор приложения управляет справочником, но не получает доступ к чужим медицинским данным.
- Одноразовый код имеет срок действия и ограничения на повторную отправку и число попыток.
